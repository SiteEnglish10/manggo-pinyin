# 当前结论与处理

用户已实际测试：基础 Ruby 标签与 Markdown 均显示为原文。版本 1.1.0 已按用户要求恢复双行纯文本，旧 Ruby/Markdown 设置自动按文本处理。不再等待 Ruby 支持来提供可读输出。宿主具体版本未知，此结论仅针对本次测试路径。

以下为历史诊断流程，正常安装使用主插件即可。

# Manggo Ruby 兼容性检查

2026-10-18：官方插件指南只有文本字符串与结构化词典接口，没有 Ruby/HTML 渲染能力声明。无法据此肯定支持，也不能断言不支持。用户的 Manggo 位于另一台电脑，本项目尚未做真实宿主验证。

## 在安装 Manggo 的电脑上验证

1. 在「关于」记录 Manggo 版本和操作系统。
2. 导入 `manggo-ruby-probe-0.1.0.mplugin`。
3. 到翻译服务添加「Ruby 渲染诊断」，先选「1. 无样式 Ruby 标签」。
4. 任意划词调用该服务。输出应是固定的「汉字 ABC 123」，汉上方 `hàn`、字上方 `zì`。诊断插件不会处理或发送选区内容。
5. 改选「2. 带样式逐字 Ruby」后再次翻译。观察注音是否在对应汉字正上方、英文是否连续、拼音是否被裁切。
6. 改选「3. Markdown 支持对照」。这只能确定 Markdown 支持，不能替代 Ruby 测试。

| 看到的结果 | 可得出的结论 |
| --- | --- |
| 第一、二项均正确 | 当前版本具备所需基本渲染能力；继续测试主插件 |
| 出现 `<ruby>`、`<rt>` 等源码 | 该输出路径未渲染 HTML，不能通过现有 Ruby 输出实现目标 |
| 标签消失但显示「汉hàn字zì」等平铺文字 | HTML 被过滤，或未执行 Ruby 排版；目标尚未实现 |
| 第一项正确、第二项错误 | 标签支持与样式支持存在差异，需要按当前宿主清洗规则调整输出 |
| 只有第三项正确 | Markdown 可用不代表 HTML/Ruby 可用 |

若前两项通过，再安装主插件，在其配置中明确选择 Ruby（旧服务可能保留 text）：

```text
重庆银行，音乐与长大。
// 初始化 cacheBuffer and return null;
const value = 123; // 缓存读取成功
繁體：銀行音樂。女绿略吗。
```

将窗口调窄，确认每字和拼音一起换行，拼音不重叠、不裁切、英文不被拆成带空格的字母。记录主插件版本、Manggo 版本、操作系统及宽窄窗口效果后，再把发行状态改为稳定版。

## 若不支持

插件公开接口没有控制翻译框 DOM 的能力，不能靠 `resultType: "html"` 等未定义字段修复。需要向宿主开发者请求：允许安全的 `ruby` / `rt` / `rp` 和必要排版样式，或提供结构化逐字注音字段。不要宣称纯文本双行是严格逐字注音的等价实现。
